## Where we are
- Known (V+I) of the lift: 6.7% LUT, 11.0% FF, 14.9% M9K, 5.7% MAC, 77.6% pads. The rest is two big blobs: `802.16-rx` (clk_pll_b: 48,870 LUT, 12,259 FF, 119 M9K, 0 MAC) and `802.16-tx` (clk_main: 33,954 LUT, 19,654 FF, 329 M9K, 82 MAC). Names are clock-domain containers only (clk_main also holds RX bit-level stages). Doc: `fpga/m2001/docs/dji-m2001-known-unknown.md`, seeds `fpga/m2001/board/blocks.json`.
- DUML path resolved both ways (#193): ground to air = 56-byte uplink record at regfile 0x44..0x7B over SPI0; air to ground = demux (11,45)/(12,47) to 2048-byte FIFO to UART TX AC11, 391 clk/bit = 256000 baud = m1400 UART2. Nothing DUML returns over SPI0. regs 3..7 = receiver address/pairing, not DUML. P0.7/P0.9 bit-bang = second RF module (RFM), not the FPGA.
- Sim (#191): Verilator runs the whole image (rtl.v 90 s build, ~19k cycles/s). Frame counter = 1,400,001 clk = 14.000 ms at 100 MHz. Ground TX slot is slaved to RX lock; forcing `ff_38_79_4` wakes the ID timer + radio-SPI engine, TX data still 0.
- Naming (#190): local Ollama gpt-oss:20b + deterministic verifier. 6 verified names (all small LFSRs/CRC in the tx blob), rx blob nothing verified. Pass 2 with the evidence-gated prompt (`46f383e67`) was started and stopped.
